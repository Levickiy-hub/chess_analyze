# Последовательность доведения до целевой системы

План основан на текущем CLI, а не на предположении о готовом веб-приложении. Этапы 0–4 блокируют доверие к дальнейшей аналитике; базовые результаты/рейтинги можно разрабатывать независимо от тяжёлого engine анализа после нормализации raw. Тесты и эксплуатационная безопасность вводятся с этапа 0, а не откладываются до последней стадии. Сроки не оцениваются.

| Этап | Цель и предварительные условия | Задачи / зависимости | Ожидаемый результат и критерий завершения | Основные риски |
|---|---|---|---|---|
| 0. Восстановление достоверности | Изолированные fixtures, сохранены original data; согласована допустимая среда запуска | B02 → B01/B03/B04, критическая часть B28; TD01–05/09 | Корректные POV/loss/mate/last position/SetUp, неизвестный игрок/Result не искажают данные, engines завершаются на всех ветках; regression suite зелёный | Существующие анализы несовместимы с исправленной методикой; не перезаписывать их без run version |
| 1. Модель и границы | Результаты этапа 0, решение local/server | B05/B26, storage часть B29 | Stable IDs, raw immutable, versioned analysis_run, FK/unique/indexes, adapters, isolated import старых 390 игр, backup/restore; никакой потери raw | Неопределённая multi-user модель; миграция ordinal IDs |
| 2. Профили и полная синхронизация | Storage и безопасный TLS runtime | B11 → B06, B28; зависит от 1 | Profile/stats и все месяцы; incremental refresh; idempotency/429/timeout/checkpoint/last_sync проверены на fixtures и ограниченной реальной проверке | API cache/currency, transient errors, неполные исторические данные |
| 3. PGN pipeline и review skeleton | Raw источник и stable games | Завершить B03; read/game части B10 | Нормализованные оба цвета, PGN tags/SAN/UCI/FEN/clocks/raw rules; quarantine; просмотр партии без engine; edge-case fixtures | Variants и нестандартные старты; отсутствующие timestamps/clocks |
| 4. Надёжный массовый Stockfish | Корректные позиции, lifecycle и run schema | B07 → B08; B27 bounded benchmark | Jobs durable/lease/retry/dedupe/pause/resume/cancel, resource budgets, per-game commit, PV/score metadata/cache; kill/restart не теряет завершённые партии | Нелинейная цена depth, WASM RSS, framing/error поведение wrapper |
| 5. Классификация и базовая статистика | Проверенные typed scores и участники | B09, core B25, review часть B10 | ACPL/engine agreement по игроку, W/L/D и причины, длины/серии/периоды, N/missing/version; доска+позиции+графики+PGN export; требования R5-8/10/12 закрыты | Некалиброванные пороги; ожидание эквивалентности Chess.com accuracy |
| 6. Рейтинг и дебюты | История и единый cohort, opening DB решение | B12/B13, B25; зависит от 2/3/5 | Format-scoped rating trends и official snapshots раздельны; ECO/варианты/транспозиции/дерево/repertoire, drill-down и sample sizes | Неполная Elo история, лицензия opening DB, разные названия вариантов |
| 7. Стадии и преимущество | Correct scores, position features и базовая статистика | B14 → B15; зависит от 4/5 | Валидированный stage classifier; показатели каждой стадии; устойчивые winning/equal/losing transitions, conversion/comebacks/decisive errors | Границы стадий субъективны; cp oscillation и mate требуют отдельной методики |
| 8. Время и сессии | Clock/time_control parser, UTC timestamps | B19 → B20; зависит от 2/3/5 | Increment-aware spent, time trouble, timeout outcomes, session gap/timezone/day-of-week; пропуски явно показаны | Daily и incremental clocks, missing first clock; ложные психологические интерпретации |
| 9. Тактика и позиционные признаки | Board state, PV и размеченный corpus | B16/B17; зависит от 3/4/7 | Каждый motif/feature имеет detector/version/confidence/evidence, negative examples и measured precision; UI списки позиций | Большая сложность объяснения причин ошибок, false positives |
| 10. Эндшпили | Stage/material classifier, выбранная tablebase политика | B18; зависит от 4/7 | Типы окончаний, stats, теоретические WDL/DTZ с coverage/rule50, outcome-changing moves | Размер таблиц/сеть, вариантные правила; не подменять heuristic теорией |
| 11. Соперники и навыки | Достаточное покрытие history/features, общий cohort | B21 → B22; зависит от 6–10 | Head-to-head и rating bands; skill formulas/rating/format/N normalization, тренды и drill-down | Малый N и несопоставимость периодов; composite score может скрывать пробелы |
| 12. Рекомендации | Skills/features валидированы | B23; зависит от 8/11 | Ранжированные рекомендации с примерами и обоснованием, тренировочный план и tracking эффекта | Непроверенная причинность; privacy при optional LLM |
| 13. Персональные тренировки | PV/motifs/tablebase и рекомендационный слой | B24; зависит от 4/9/10/12 | Проверенные задачи из игр, alternatives, difficulty, hints, попытки и spaced repetition; полноценный interactive flow | Неединственность решений, unstable engine line, плохая оценка сложности |
| 14. Эксплуатационная готовность | Все обязательные продуктовые этапы, целевой масштаб определён | Закрыть B27/B28/B29, E2E/CI по B02 | Benchmark на согласованном объёме, resource caps, recovery/backup/upgrade/rollback, notices/docs, security/access checks и end-to-end flows зелёные | Нельзя компенсировать корректность и recovery одним процентом feature coverage |

Этапы 8–10 частично параллельны после выполнения входных условий, но это не инструкция запускать несколько агентов в рамках аудита. Для каждого gate требуется артефакт проверки, а не только наличие файла/кнопки. Полностью проверенные функции chess.js, raw сохранение и базовые counts повторно не разрабатываются; их контракты включаются в регрессию. Старые результаты сохранять с пометкой legacy/untrusted методики, повторный engine запуск согласовать отдельно.
