# Итоги комплексного аудита

Дата: 24 ноября 2026. Объект: D:/stockfish. Исходный код, конфигурация и старые данные не менялись; новые материалы находятся только в docs/audit. До аудита этого каталога не было. Выводы относятся к доступному файловому snapshot, а не к неизвестным веткам или внешним сервисам.

## Фактическое состояние

Это небольшой Node.js CLI прототип пакетного анализа последнего месяца Chess.com с сохранением JSON/PGN и статическими HTML отчётами. Это ещё не приложение комплексной персональной аналитики всей истории. Веб-сервера, frontend framework/доски, СУБД, persistent jobs, API продукта, CI и рабочего test suite нет. В рабочем каталоге отсутствует .git; история и состояние Git недоступны.

Стек: JavaScript ES modules, Node v24.19.0 и npm 11.17.0 в текущей среде; chess.js 1.4.0; @se-oss/stockfish 1.0.1; Stockfish 17.1 WASM Multithreaded; HTML/CSS/SVG, встроенный filesystem и JSON/PGN. Package-lock соответствует установленным двум зависимостям; чистая установка не выполнялась. Версии runtime не зафиксированы проектом.

390 локальных партий, 30 607 полуходов, 390 отдельных JSON и 391 HTML. Все 390 исходных PGN загрузились chess.js, длины совпадают с analysis. Данные имеют реальную структуру Chess.com и не генерируются mock-кодом приложения; их сетевое происхождение заново не подтверждалось. Из объектов API сохраняются все поля game, но не envelope/HTTP headers. В выборке rapid и daily смешаны, rules=chess.

## Работоспособность и проверенные возможности

- 8/8 собственных JS проходят node --check; модули PGN/статистики/адаптера импортируются.
- Один реальный Stockfish успешно инициализирован и выполнил три поиска depth4 с Threads=1 Hash=16; процесс аудита явно завершён.
- PGN/SAN/UCI-FEN обработка стандартных игр, рокировка/en-passant/promotion/mate на коротких fixtures работают через chess.js.
- Существуют raw cache, per-ply pre-position score/bestMove, parallel pool/FIFO и console progress, экспорт анализа и автономные HTML.
- generateSummary(saved) воспроизводит summary.json без повторного движка; простые W/L/D на локальной выборке 198/154/38.
- API adapter success/404/429/503 проверен только с подменённым fetch. Никакого real Chess.com запроса и запуска main не было.

Полный запуск приложения **не подтверждён**. Прямой node index.js выбрал бы весь месяц, pool16 и перезапись результатов. Главный CLI может не завершаться из-за незакрытых дочерних процессов; это установлено кодом и fake-engine проверкой close, а не выполнением массового main. npm test завершился exit1, потому что это заглушка. Сборочных проектов/frontend/backend build scripts нет, поэтому результат «сборка приложения прошла» не заявляется.

## Критические проблемы

1. TD01: side-to-move score сравнивается без нормализации. Одинаковый белый перевес +100/-100 даёт ложные 200 cp потери.
2. TD02: ACPL исключает нулевые потери и смешивает обе стороны; engine agreement тоже считается по обоим игрокам. 507.3 cp в старой сводке нельзя считать личным ACPL.
3. TD03/TD05: SetUp/FEN при повторном проигрывании игнорируется, отсутствующий пользователь становится чёрными, Result=* становится поражением.
4. TD04/TD06: close не terminate; нет cleanup main/partial init, durable jobs и промежуточной записи; один rejected Promise срывает сохранение.
5. TD07/TD14: только последний архив, устаревающий кэш без TTL, нет retries/HTTP policy/checkpoint/полной истории.
6. TD09/TD10: финальная позиция не анализируется, mate теряется в классификации, стадии назначаются по третям длины партии.
7. TD11/TD12: HTML не экранирует headers, cp подписаны пешками, unknown/mate превращены в 0; пустой график даёт NaN, null date ломает ссылки.
8. TD13/TD17: runtime warning указывает на отключённую проверку TLS; источник не установлен. Тестов/CI нет.

Старые raw/PGN пригодны для дальнейшего использования; старые quality результаты следует сохранять как legacy и не использовать для персональных рекомендаций без исправления методики/версий. Повторный анализ не запускать автоматически в рамках аудита.

## Рекомендуемая последовательность и первые десять задач

Этапы: регрессии и P0 корректность → модель/ID/provenance → профили/полный sync → PGN/review → durable Stockfish jobs → базовая статистика → рейтинг/дебюты → стадии/преимущество → время/сессии → мотивы/позиции/эндшпили → навыки/рекомендации → тренировки → подтверждение эксплуатации. Критерии каждого этапа в IMPLEMENTATION_ROADMAP.md, проверка/безопасность идут с начала.

1. **B01 Исправить POV, loss и матовые оценки** — P0, L; зависимости B02.
2. **B02 Создать минимальную регрессионную базу и проверки** — P0, M; зависимости —.
3. **B03 Нормализовать PGN, участника и начальную позицию** — P0, L; зависимости B02.
4. **B04 Исправить lifecycle процессов и управляемое завершение** — P0, M; зависимости B02.
5. **B05 Добавить устойчивые ID, транзакционную модель и provenance** — P0, XL; зависимости B02.
6. **B06 Реализовать полный и инкрементальный Chess.com sync** — P0, L; зависимости B05,B11,B28.
7. **B07 Закрыть Stockfish типизированным адаптером** — P0, L; зависимости B01,B04,B05.
8. **B08 Реализовать persistent queue массового анализа** — P0, XL; зависимости B03,B05,B07.
9. **B09 Исправить базовую статистику, agreement и ACPL** — P1, L; зависимости B01,B03,B05.
10. **B10 Создать read API и интерактивный game review** — P1, XL; зависимости B03,B05,B07,B28.

B11 (профили) — необходимый предшественник B06, B28 — сетевой безопасности. Нумерация первых десяти — приоритет задач, а не попытка игнорировать DAG. Полный backlog: 29 пакетов и 639 поэлементных дочерних задач по пробелам/проверкам. Подтверждённые реализованные требования не включены в повторную разработку.

## Ограничения и вопросы

Проверки модулей, 390 PGN и короткий engine smoke не заменяют их. Подробно VERIFICATION_REPORT.md.

Перед разработкой решить: local/server и owner model (Q01), определение accuracy и порогов (Q05/Q06), CPU/RAM/размер истории (Q08), где официальный Git (Q09), источник TLS политики (Q10), UI поставка и лицензии/privacy (Q12/Q14). Остальные варианты и рекомендуемые решения — OPEN_QUESTIONS.md. Исходники и текущие config values не являются открытыми вопросами.
