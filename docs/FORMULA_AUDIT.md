# Проверка формул — 26 ноября 2026

Проверены расчёты нормализации PGN, оценок UCI, качества ходов и ACPL, результатов и серий, рейтингов, дебютов и стадий, реализации и возвратов в игру, времени и сессий, позиционных признаков, профиля решений, тренера и тренировок. Проверка включает чтение реализации, воспроизводимые примеры, инварианты на реальной базе и отдельный запуск Stockfish.

## Исправленные ошибки

| Область | Ошибка и исправление |
| --- | --- |
| Оценки Stockfish | `lowerbound`/`upperbound` могли попадать в вычитание как точные оценки. Границы сохраняются с правильным направлением для белого POV, показываются как ≥/≤ и исключаются из точных расчётов качества и реализации. |
| Неизвестные оценки | Невалидный тип/значение оценки больше не получает категорию «отличный» и числовой балл. Отсутствующий лучший ход не совпадает с отсутствующим UCI. |
| Пропущенный мат | Совпадение с лучшим ходом при шуме между двумя поисками могло одновременно получать признак пропущенного мата. Теперь признак подавляется для лучшего хода, как и остальные потери. |
| Ничьи | Право заявить ничью после 50 ходов не подменяет поиск автоматическим нулём. Мат имеет приоритет; обязательные 75 ходов и пятикратное повторение учитываются. История передаётся в поиск и проверяется на соответствие позиции. Старый сомнительный ноль помечается неизвестным до нового поиска. |
| Разница рейтингов | Вычитание `null` давало фиктивную разницу. Теперь нужны оба конечных числовых рейтинга; иначе группа «Неизвестно», числовой фильтр не проходит. |
| Устойчивый перевес | Фильтр отдельных ходов мог сделать несоседние ходы «последовательными». Проверка вынесена в общий помощник и работает по полному анализу выбранных партий; пропуск оценки или полухода сбрасывает серию. Радар сохраняет явное отключение реализации при фильтре отдельных ходов. |
| Время партии | PGN с одной датой получал фиктивное начало в полночь. Дата без времени больше не образует сессию и почасовую активность. Проверяются календарная дата и формат часов. |
| Время обдумывания | Для произвольной начальной FEN нельзя считать исходным остатком базовое время контроля. Первый расход неизвестен; последующие расходы считаются по часам той же стороны с инкрементом. Неполные интервалы не склеиваются. |
| Цейтнот | Заочные и неподдерживаемые контроли исключены из live-метрик. Совет о снижении качества требует достаточного числа оценённых ходов в обеих группах одного формата; `null` больше не заменяется нулём при сравнении. |
| Исход по времени | Ничья `timevsinsufficient` больше не считается поражением по времени. Последний известный остаток действительно ищется среди ходов с сохранёнными часами. |
| Сессии | Группировка использует время начала, если оно известно и корректно. Предыдущий результат и номер партии восстанавливаются по полной live-истории до фильтров. Изменение наблюдаемого рейтинга использует только рейтинговые партии одного формата и соответствующие конечные точки. |
| Серии | Партии без точного времени не формируют фиктивную хронологическую серию; число исключений доступно в отчёте. Серии по фильтрованной выборке по-прежнему относятся только к ней. |
| Тактические признаки | Атаки собственного короля могли создавать ложную вилку другой фигурой. При геометрической проверке оставляется только проверяемая фигура. Неразвитые кони и слоны проверяются на своих соответствующих начальных полях. |
| Округление | Изменение частоты ошибок тренера вычисляется из исходных долей и округляется после вычитания, а не до него. |
| Генерация задач | Недостающий второй вариант ошибочно давал разрыв 1. Теперь требуются два разных легальных первых хода, одинаковая глубина ≥8 и точные оценки без границ. Разрыв остаётся эвристическим порогом модели. Длина PV больше не выдаётся за сложность задачи: показывается число ходов решающего. |
| Повторение задач | Досрочное повторное решение не удваивает ещё не наступивший интервал. Отдельно считаются успешные попытки и уникальные решённые задачи. Завершённый/неправильный по очередности префикс не даёт подсказку и не засчитывается как новый этап. |
| Прогресс заданий | Процент обработки анализа учитывает успешно завершённые и неудачные партии; повторяющиеся ID внутри запроса дедуплицируются. |

## Проверенные зависимости и правила

- Нормализация знака cp и матового победителя проверяется симметричными примерами за оба цвета; мат в 0 означает поражение стороны, которой принадлежит ход.
- Геометрические атаки chess.js не равны возможности сделать легальный ход: связанная фигура тоже может считаться атакующей. Такие признаки продолжают называться эвристиками. [Документация chess.js](https://github.com/jhlywa/chess.js/blob/master/website/docs/index.md).
- Право заявить ничью и автоматическое окончание различаются в статьях 9.2, 9.3 и 9.6. Мат на последнем ходе имеет приоритет перед правилом 75 ходов. Это важно для анализа произвольных позиций; результат импортированной партии берётся из PGN. [Правила FIDE](https://handbook.fide.com/chapter/e012023).

## Применение к существующим данным

Формулы производных оценок имеют версию `personal-v3`, нормализация партий — версию 2. Старые данные пересчитываются при чтении и кэшируются в памяти. Исходные PGN, сохранённые позиции движка и записи исторических анализов не перезаписываются. Для этого пересчёта массовый поиск Stockfish не нужен. Ключи кэша поиска сохранены совместимыми: результат поиска не зависит от формулы качества. Сомнительный старый ноль по правилу 50 ходов не переиспользуется новым поиском.

Результат проверки реальных профилей сохранён в [formula-audit-results.json](formula-audit-results.json). Там приведены агрегаты и число исправленных производных признаков, без PGN. Значения относятся к снимку базы во время проверки и будут меняться после новых партий.

## Что остаётся условным

- Общий показатель качества `100 × exp(−4 × потеря модельного результата)` — выбранная модель, не Chess.com accuracy и не калиброванная вероятность победы. Сжатие оценок в уже решённых позициях сохраняется как ограничение этой модели; новый радар использует другую формулу и отдельные диапазоны.
- Радар — индекс сохранения оценки с выбранным пределом штрафа 300 cp и равным весом партий. 30 ходов в пяти партиях — правило минимальной выборки, не статистическая гарантия точности. Сравнение по рейтингу не калибровано.
- Стадии, тип окончания, опасность короля, развитие, вилки и связки — эвристики. Нет доказательства причин ошибки и нет таблиц эндшпилей Syzygy.
- Средние по ходам и средние по партиям отвечают на разные вопросы. Общая аналитика использует ходы; индекс радара сначала считает внутри каждой партии. Площадь радара не трактуется как общий навык.
- Рейтинг — наблюдаемое значение до партий, не точное изменение после последней партии. Сессии при неизвестном начале используют время окончания. На графике сессий показаны первые 20 позиций.
- Более строгая проверка двух вариантов применяется к новой генерации задач. Сохранённые ранее решения автоматически не перепроверяются: для этого потребовался бы дополнительный поиск.
- PV — найденный вариант при ограниченном поиске. Разрыв между двумя первыми ходами не доказывает единственность всех последующих ходов; тренировка требует воспроизведения сохранённого продолжения.
- Различия соперников, сложности позиций, глубины и режима анализа могут менять показатели даже при одинаковом формате и периоде. Проверки не доказывают отсутствие всех возможных дефектов и не превращают эвристики в измерение силы игрока.

## Результат проверки

Прошли 62 модульные и HTTP-проверки, два теста с настоящим Stockfish, синтаксическая проверка 17 модулей и инварианты на 2504 партиях двух профилей. После обновления сервера проверены API обоих профилей и интерфейс сессий, времени и тренировок. На реальной базе удалены 371 ложный признак вилки; одна старая нулевая оценка требует нового поиска и исключена из расчётов.
